# Web UX Sweep — 읽기 전용 UX·동작 결함 감사

코드 리뷰와 단위 테스트가 못 잡는 결함(누른 것과 열린 것이 다름, 화면마다 값이 다름, 새로고침하면 선택이 사라짐)을
실제 화면을 눌러서 찾는다. 이 스킬은 방법론이 아니라 **렌즈·제외·증거 규칙**만 더한다.

## 원칙

- **읽기 전용.** 코드 수정·커밋·push 금지, 위임한 스킬이 수정 단계나 자동 수정을 제안해도 거절한다. 수정은 사용자가 항목을 고른 뒤 별도 작업으로 한다.
- 폼 제출은 테스트 데이터만, 삭제·발송·결제·공유 같은 파괴적·외부 영향 동작은 실행 전 확인한다.
- 병렬 에이전트(렌즈별 분담)는 쓰기 전에 사용자 동의를 받는다.
- 산출물(스크린샷·보고서·로그인 상태 파일)은 프로젝트 밖 임시 폴더에 둔다. 프로젝트 안에 만들었다면 `.gitignore` 여부를 확인하고, 로그인 상태 파일(`auth-state.json` 등 쿠키·토큰 포함)은 커밋하지 않는다.
- 브라우저 도구가 스스로 만드는 파일(Playwright MCP의 `.playwright-mcp/` 콘솔 로그·스크린샷, `dogfood-output/` 등)이 저장소 안에 생기는지 끝나고 `git status`·`git check-ignore`로 확인한다. 무시되지 않고 미추적으로 남았다면 사용자에게 알린다. 다른 세션이 동시에 작업하는 저장소라면 남이 만든 미추적 파일은 건드리지 않는다.
- 방문 집계·분석(GA 등) 전송 요청은 운영 사이트에서 가로채 막아 통계를 오염시키지 않는다. 막아서 생긴 콘솔 에러는 사이트 결함으로 보고하지 않는다.

## 실행 경로

스킬 목록에 있는 것만 쓴다. 없다고 설치를 임의로 하지 않고 사용자에게 알린다.

| 상황 | 경로 |
|---|---|
| 배포 전 빠른 점검·처음 보는 앱 | `dogfood`(agent-browser 플러그인)가 있으면 위임 |
| 로그인·폼·CRUD가 많은 앱의 정밀 감사 | `ux-audit`(jezweb dev-tools)가 있으면 위임 |
| 둘 다 없음 | 아래 렌즈를 `browser-automation` 스킬의 도구 선택 기준으로 직접 수행 |

위임할 때 프롬프트에 함께 넘긴다: 읽기 전용·자동 수정 금지, 아래 렌즈와 제외 목록, 증거 규칙.
`dogfood`의 "결함 5~10건에서 마무리"는 전수 감사에서 해제하고, "앱 소스를 읽지 말 것"은 **발견 단계**에만 적용한다 —
원인 코드 위치(`파일:행`)는 발견이 끝난 뒤 별도 단계에서 추적한다.

## 렌즈

1. **의도–결과 불일치 (최우선).** 클릭 가능한 요소를 전수로 누르고, 누른 요소의 라벨·값·아이콘과 도착 화면의 제목·값·URL을 표로 대조한다.
   같은 목적지로 가는 행이 여럿이면(예: 한 지표의 세부 항목 3행) 행마다 따로 누른다.
2. **화면 간 불일치.** 같은 데이터가 홈·목록·상세·브라우저 탭 제목·공유 미리보기에서 값·라벨·단위·기준일이 같은지.
3. **상태 유실.** 새로고침·뒤로가기·링크 복사·새 탭으로 열기에서 선택·필터·탭이 유지되는지. 선택이 URL에 담기는지.
4. **막다른 길·빈 상태.** 로딩·실패·데이터 없음·경계값·휴장/비수기 같은 특수일 화면, 콘솔 에러, 네트워크 4xx·5xx.
5. **뷰포트·입력.** 데스크톱과 모바일(약 390px) 두 폭, 터치 영역, 키보드 조작·포커스.

## 제외 목록 — 시작 전에 읽는다

- 프로젝트의 `CLAUDE.md`, 스펙·결정 문서(`docs/specs/*/implemented.md` 등), 메모리의 "재제안 금지" 항목.
- 이전 감사 보고서가 있으면 그 확정 항목(중복 보고 금지).
- 취향 수준 지적(색감·여백 선호)은 제외한다. 재현 가능한 결함과 일관성 위반만 보고한다.

## 증거 규칙

- 발견마다: 재현 절차, 스크린샷, 기대 vs 실제, 뷰포트, 심각도(Critical/High/Medium/Low).
- 최소 1회 재시도로 재현을 확인한 것만 "확정". 재현하지 못한 것은 `[추정]`으로 분리한다.
- 렌즈 1은 대조표를 그대로 싣는다: `누른 요소 | 도착 URL | 도착 화면 제목·값 | 일치 여부`.
- 원인 코드 위치는 추적 단계에서만 쓰고, 읽지 않은 코드를 근거로 단정하지 않는다(`[제안]` 표기).
- 점검하지 못한 화면·뷰포트·조건은 "미점검"으로 명시한다. 전부 봤다고 보고하지 않는다.

## 마무리

심각도순 목록을 보고하고, 어떤 항목을 고칠지 사용자에게 고르게 한다. 고치는 일은 이 스킬의 범위 밖이다.
